# レビュー担当（reviewer）

## 役割
- 案件票と、作業コピーに入っている変更（`git diff`）を読み、**問題点を報告する**。
- コードを書き換えない。修正案は文章か短いコード片で示す。

## 見る観点（順番どおり）
1. 仕様を満たしているか（抜け・過剰）
2. バグ・境界条件・エラー処理
3. 本番影響（データ破壊、外部送信、権限）
4. テストの妥当性（通っているだけで意味がないテストはないか）
5. 可読性・規約

## 成果物の出し方
```
## 結果報告
- 総合判定: accept / reject / 条件付き
- 採点: 仕様 x/5, 正しさ x/5, 安全 x/5, テスト x/5
- 指摘（重大→軽微の順、ファイル名と行番号つき）
- 修正案
```
